# new-post

把 `公司/` 下的一场面经，转成 `发帖/` 下的一篇发帖稿。

## 硬性前提

- **只处理 `source: 我面试` 的面经。** frontmatter 是 `网上转载` 的一律不做——转载别人的内容发成自己的面经不合适，直接告诉用户并跳过。
- 一场面试一个帖子，不合并。

## 执行步骤

1. 定位源文件（用户没指明就按日期找最近的），确认 `source: 我面试`。
2. 写到 `发帖/<面经标题>_发帖.md`。
3. 跑 `python3 wiki/scripts/lint_wiki.py`（发帖稿在 `发帖/` 不在 `wiki/`，lint 不检查它，但顺手确认没把别处改坏）。

## 文件模板

````markdown
# <公司> <轮次> · 发帖稿

> 源：[[公司/…/…]] · <日期> · <结果>
> 匿名规则：项目按方向命名 —— 不带公司名、不出现实习段数。见本文件

---

**标题：** <公司><渠道简称> <方向> 一面

**正文（直接粘贴）：**

```
<渠道行，如：人才计划。／提前批。／暑期实习岗，但一定要先来实习才能转秋招。>
<一句话性质：没有八股，全程围绕项目拷打，外加一道算法。>
结果：<挂／过，约下轮／未知，当天面完>

【一、<分组>】
1. …
2. …

【二、<分组>】
1. …

<固定结尾语>

<标签行>
```
````

## 正文规则（这些是用户逐轮改出来的，别自作主张改回去）

**只写被问了什么，不写怎么答的。** 不放参考答案、不放复盘、不放避雷提醒、不放「几点体会」。答案留在源面经里。

**开头不要这些：** 时间、时长、形式（视频面/投屏）、岗位方向。只留三行——渠道、一句话性质、结果。

**「一句话性质」怎么写：**
- 没有八股、只问项目 → 「没有八股，全程围绕项目拷打」+ 补算法情况
- 也没问数据库/Java → 「没有八股，也没问数据库和 Java，全程围绕项目拷打」
- 不是问项目的场次（比如全是实操题）→ 照实写，别硬套「围绕项目拷打」

**问题措辞：** 压缩成陈述句，句号结尾，不用问号。参考：「决策树的节点、边、分支分别是怎么定义的。」不要写成「决策树的节点、边、分支分别是怎么定义的？」

**分组方式：** 各项目（一个项目一组，用方向命名）/ 概念题 / 算法 / 手写题、实操题（一题一组，带题面）。每组内部从 1 重新编号，组号连续。

**只列技术问题。以下两类一律不列：**

1. **个人相关的问题** —— 开场摸底、职业规划全都不要。包括但不限于：自我介绍、技术栈是什么、毕业时间、什么时候能到岗／入职、能实习多久、城市意向、对岗位有什么预期、实习节奏是不是规划好的、来了想做哪个方向。**「开场摸底」「职业规划类」这种分组直接整块删掉，后面的组号往前挪。**
2. **反问环节** —— 用户自己问的问题不写，对方回答里的部门情报、组织情报也不写。

**唯一例外：** 如果面试官在这两类话题里追问了技术内容（比如反问时反过来考你一个技术判断），那一条要留，归到对应的技术分组里去。

## 匿名铁律

要防的不只是「雇主名」，是**准标识符**（quasi-identifier：单看无害、几条凑在一起就能把人锁定的信息）。三类都要清。

### 1. 直接标识

- **绝不出现用户任何一段实习的雇主名**，也不出现能反推的项目代号（如 DeerFlow）。用户明确不希望对外暴露在谷歌实习这件事。
- **在职项目的内部框架名、内部系统代号一律不写**（源面经的自评里把这条列为保密红线第一条）。
- **面试官姓名不写。**
- **学校、城市／地域意向不写。** 连「城市意向」这种只有问法、没有答案的也删掉——用户明确要求。
- **面试的那家公司要写**——那是面经的主体，标题和标签都带。

### 2. 数量与顺序

**项目分组用方向名（优先），编号也可以，但绝不出现总段数。**

| 写这个 ✅ | 也行 ⭕️ | 不要写 ❌ |
|---|---|---|
| 【Agent 记忆系统项目相关提问】 | 【实习一项目相关提问】 | 【五段实习里的第一段…】 |
| 【多 Agent 问答系统项目相关提问】 | 【实习二项目相关提问】 | |

方向名优先只是因为信息量更大（读者一眼知道这组问什么）；用户明确说过**「实习一二三」这种编号本身没关系，一般也问不到 5**。真正要防的是**总段数**——五段实习的候选人少，是强特征。

**问题正文里的数量词和时间跨度要洗掉：**

| 原话 | 改成 |
|---|---|
| 五段实习里你自己最熟悉哪一段 | 简历里你自己最熟悉的是哪个项目 |
| 从今年 1 月起每段实习都是 3 个月，是规划好的吗 | 你每段实习时间都不长，是规划好的吗 |
| 讲一下你在字节的实习工作 | 讲一下你这个项目具体做的工作 |
| 你这两段经验里能不能着重讲… | 你的项目经历里能不能着重讲… |

**统一把「这段实习」改成「这个项目」**——前者暗示在数实习，后者不暗示任何数量。

### 3. 简历专属数字

准确率 56%→87%、200+ 用户、40 多个仓库、五段实习——这类只出现在这一份简历上的数字**一律删**。问题里保留问法即可（「准确率是怎么测评的」），不带具体值。

### 交付前自查

```bash
grep -rn "谷歌\|字节实习\|你在字节\|Arm\|西门子\|用友\|DeerFlow\|[一二三四五]段实习\|这段实习\|学校\|城市" 发帖/<新文件>
```

有输出就是没洗干净。

## 固定结尾语（五篇统一，不要每篇换说法）

```
秋招信息差太大了，想找组织一起交流。同投 Agent／大模型岗的友友对对流程
```

## 两个版本：牛客版 + 小红书版

每篇发帖稿出**两版**，用 `## 牛客版` / `## 小红书版` 两个小标题分开，各自带 `**标题：**` 和一个可直接粘贴的代码块。

**正文内容两版逐字一致**，只有三处不同：

| | 牛客版 | 小红书版 |
|---|---|---|
| 标题 | 带「秋招」等限定词，可长一点 | 更短，20 字以内，平实不标题党 |
| 标签写法 | 双井号 `#秋招# #面经#` | 单井号空格分隔 `#秋招 #面经` |
| 标签内容 | `#秋招# #面经# #校招# #<公司># #agent# #大模型#` + 按场次加 | 加 `#秋招面经` `#26届秋招`，其余按场次挑 |

**标签要跟内容对得上**——支付/后端的场次别挂 `#AI大模型`，Agent 场次别挂 `#后端开发`。

## 何时不该用这个 skill

- 用户要的是**复盘**（分析答得好不好）→ 用 `new-review`
- 用户要的是**入库**（把面经收进仓库、更新画像和索引）→ 用 `wiki-maintain`
- 源面经是网上转载 → 直接说明不做

## 收尾

告诉用户文件路径（markdown 链接）+ 这篇分了几组共多少题。**不要替用户发布**——登录牛客/小红书发帖是对外发布，只交付可直接粘贴的稿子。
