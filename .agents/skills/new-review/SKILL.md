# new-review

两个模式：**模式一**开一份新复盘（刚面完）；**模式二**把已入库的面经逐题过稿（打磨答法）。

---

## 模式二：逐题过稿

**触发**：用户说「一题题过 / 我们讨论怎么答好 / 过一遍这场的问题 / 我的回答有什么问题 / 把所有问题列出来」。

### 题目范围

从 `公司/` 下对应面经读取全部题目和现场回答，但复盘队列只保留：

- **技术题**：项目机制、系统设计、通用知识、技术取舍、故障与实现追问。
- **HR 判断题**：答案存在取舍、会影响录用判断的题，例如求职动机、职业方向、岗位/团队选择、实习切换与稳定性、组织评价。

**个人情况题不进入逐题复盘。** 跳过教育与 gap 时间线、毕业/返校时间、回国安排、城市/籍贯、家庭/感情、工作地点、可入职时间等只需说明事实的问题；这类题只需保证口径真实一致，不值得占一轮讨论。自我介绍、寒暄、面试官介绍和反问环节同样跳过。

个人情况被连续追问时，只抽取后来真正考察职业选择或稳定性的那一道追问。例如「什么时候毕业」跳过；「为什么连续换三段实习」「如果原团队给留用还会不会回去」保留。用户主动点名个人情况题时，只帮他压成 10～15 秒的事实口径，不按完整四段格式复盘。

### 每题开始前：先找仓库里的旧答案

用题目关键词、项目名和核心概念在仓库里搜索，不能只看当前面经。搜索优先级：

1. `wiki/追问/`、`wiki/我的简历/`：定稿口径与项目 ground truth。
2. `公司/`：以前面试中出现过的同题及当时回答；**排除当前面经文件**。
3. `wiki/技术主题/`、`wiki/Agent问题答案/`：通用知识答案。

用 `rg -n` 搜同义词和旧叫法，打开候选文件确认标题和正文后再给链接。链接必须落到具体章节：

- raw 面经：`[[公司/公司名/BU/文件名#题目标题]]`
- 追问库：`[[追问/项目名#问题标题]]`
- 技术主题：`[[主题名#章节标题]]`

把结果分成两类，不能混写：

- **同题**：提问目标相同，标「以前答过」。
- **相关素材**：只能支持部分答案，标「相关」，不能冒充以前答过。

最多给 1～3 个最相关链接。没找到就明确写「仓库里未找到同题，按新题处理」，不许硬编链接。

### 逐题节奏

用户说「一道道来 / 一题题过」时，**不先总览，不一次列多题**。按面试时间顺序，从第一道符合范围的题开始。第一轮固定只给：

1. **现场问题**。
2. **这场当时的回答**：原话或忠实压缩，不加评价。
3. **仓库内同题 / 相关素材**：只列已核实的具体章节链接。

然后停下，等用户先判断哪里不对、准备怎么改。此时不提供分水岭、建议或定稿稿件。

用户要求「把所有问题列出来」时，才整体列过滤后的题目；每题只给「开口第一句 + 2～3 个支撑点 + 分水岭」。

用户给出自己的判断后，反馈固定四段：**留什么 / 删什么 / 补什么 / 定稿口语稿**。评估固定看四项：开口第一句 / 有没有踩中分水岭 / 能不能 40 秒收口 / 术语准确度。

用户确认定稿后，把新口径**回写进面经文件**，并在文件顶部「复盘要点」加一条。

🔴 **铁律：AI 不知道用户当场说了什么。**
面经文件里没有「当时的回答」那一栏就是**真的没有**——**不许推测、不许用「你大概是这么答的」开头、不许把自己起草的定稿版说成用户的原话**。
用户想不起原话时，给**这题的典型失败模式清单**让他对号入座，然后往下走，不要卡在这里。
如果能从现场证据反推（比如**同一主题被连追三次 = 前两次没答到**），可以说，但要标明是推断。

## 模式一：开一份新复盘

## 执行步骤

1. 从用户的话里抽出 `<公司>` 和 `<轮次>`：
   - 公司：用户提到的公司名（如"字节" / "快手" / "腾讯"），不要带"公司"两字
   - 轮次：默认 `一面`；用户说"二面 / leader 面 / hr 面 / 二进宫"等就用对应词

2. 跑脚本：
   ```bash
   bash wiki/scripts/new_review.sh <公司> <轮次>
   ```

3. 把脚本输出原样给用户。文件路径要可点击（用 markdown 链接）。

4. **不要**自动开始填这个文件——复盘必须用户自己填，AI 不知道用户答了什么。

5. 提醒用户：
   - 30 分钟内填完
   - 答崩的考点 → wiki/索引/高频考点榜.md 自评 -1
   - 算法新真题 → wiki/算法/README.md 加进清单
   - 公司画像 → 把这场记录到 wiki/公司/<公司>.md

## 何时不该用这个 skill

- 用户问"我该怎么复盘"——回答方法，不创建文件
- 用户已经在编辑复盘文件——直接帮编辑就行
- 用户要看复盘示例——指 wiki/复盘/示例-2026-05-04-假想字节复盘.md

## 何时主动建议

如果你看到用户消息提到"刚面完 / 面试结束了 / 答崩了 / 答得不错"等明显刚结束面试的语气，主动问一句"要建一份复盘吗？/new-review 帮你打开模板"。
