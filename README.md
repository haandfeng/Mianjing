# MianJing

个人面试与学习知识库：保存来源、逐题复盘、维护技术主题与项目追问，通过链接连接面经和当前知识。

第一次使用先读 [使用指南](wiki/使用指南.md)。算法在另一个仓库。

## 资料与 wiki 的区别

| 目录 | 维护什么 |
|---|---|
| `资料/面经/` | 按公司、业务方向归档的单场面试，保留问题、当时回答与当时复盘 |
| `资料/学习材料/` | 外部文章摘录、历史学习笔记与参考材料，按后端、Agent、系统设计分类 |
| `资料/项目参考/` | 第三方课程、项目候选资料、脚本与 PDF，不代表本人做过这些项目 |
| `wiki/公司画像/` | 跨多场面经汇总问题、业务差异、准备重点与来源 |
| `wiki/技术主题/` | 每个技术主题的一份当前解释与面试答案 |
| `wiki/项目追问/` | 本人项目的具体设计、决策与完整追问答案 |
| `wiki/我的简历/` | 本人经历和项目事实的核对依据 |

**资料保存“来源是什么、当时怎么答”，wiki 维护“现在如何理解、如何回答”。** 面经保留当时的改进摘要，完整通用答案链接技术主题；公司画像、Agent 问答也引用主专题。项目事实以 `wiki/我的简历/` 为准，完整项目答案放在项目追问。

本次将原 `公司/`、`专栏/`、`项目/` 分别整理到资料下；原 `wiki/公司/`、`wiki/追问/` 改为公司画像与项目追问。已完成的 [LLM Wiki 与 RAG 文章](<wiki/技术主题/LLM Wiki与RAG的区别及适用场景.md>) 从原专栏迁入技术主题。其余学习材料保留来源和历史语境，后续新增当前知识时先查现有主题，避免重复维护。

TikTok / TT 面经统一归入 `资料/面经/字节/TikTok/`，公司填写“字节”，保留具体业务方向。
