# 使用指南

> 个人面试 + 学习知识库的 SOP。**只做 4 件事**——本页是这 4 件事的端到端操作。

```
0. 装插件（一次性）
A. 加新面经       ← 最常用
B. 找面经 / 看公司爱考什么
C. 学习专题
D. 加新专题       ← 第二常用
```

---

## 0. 装插件（一次性 5 分钟）

打开 [[插件设置]]，必装 **Dataview**（dashboard 全靠它）。其他选装。

测试：装完打开 [[dashboard/面试历史]]，能看到表格而不是代码块。

## 索引、日志与搜索（每次操作都适用）

### 找内容

1. 先读 [[index]]，根据一行摘要选择相关页面，再读正文和原始来源。总索引覆盖 `wiki/` 内的 Markdown 页面；原始面经、专栏、项目从对应页面的双链进入。
2. 需要了解最近做过什么时，读 [[log]] 末尾记录；内容日期以原文为准，日志日期表示操作发生的日期。
3. 索引定位不够精确时，用 Obsidian 全文搜索，或在仓库根目录运行关键词搜索：

```bash
rg -n -i 'RAG|混合检索|重排' wiki 资料 -g '*.md'
```

`rg` 输出匹配的文件、行号和原文；可把关键词替换为题目中的术语及同义表达。搜索结果用于定位，回答前仍要读上下文和来源。

### 维护总索引

- 每次入库后，检查 [[index]] 与受影响的分类索引、公司画像。
- `wiki/` 新增、删除或重命名页面时，同步增删、修改总索引条目；页面主旨变化时更新一行摘要。
- 每个页面一条双链和一句摘要，按现有类别归档。总索引自身不列为条目；脚本、图片、外部简历文件不收录。

### 追加操作日志

完成一次入库、内容维护、知识库查询或复盘、wiki 检查后，在 [[log]] **末尾追加**记录。同一请求里的多次搜索合并成一条查询记录，临时定位文件或检查工具无需单独记录。

每条记录的标题统一为 `## [YYYY-MM-DD] 操作 | 标题`，日期按北京时间填写。操作使用 `ingest`（入库）、`update`（维护）、`query`（查询或复盘）、`lint`（检查）、`setup`（首次建立流程）。正文写来源或查询目的、涉及页面、实际结果；检查记录须写明运行命令和结果。

历史事件和结果保留原样；发现错误就追加更正记录。目录迁移时仅修复历史记录的链接目标，并追加迁移说明。已有内容的建档不补写为过去的入库事件，未运行的检查也不记为通过。

最近 5 条记录可这样查看：

```bash
rg '^## \[' wiki/log.md | tail -5
```

## 内容维护位置

- `资料/面经/`：保留单场问答与当时复盘，后续更正注明复盘日期；现场原话不改写成标准答案。
- `资料/学习材料/`：保留摘录、旧笔记和深入参考。归档提示中的链接指向完整主题解释，历史材料不作为另一份并行更新的标准答案。
- `资料/项目参考/`：第三方项目学习候选，与本人的实习、简历项目分开。
- `wiki/技术主题/`：完整通用解释一处维护。已有主题优先补充，短答引用对应章节。
- `wiki/项目追问/`：本人项目的完整讲述与特定追问；项目事实回链 `wiki/我的简历/`。
- `wiki/公司画像/`、`wiki/Agent问题答案/`：分别保留公司准备重点、问题短答和主专题链接，不再复制整套机制说明。

## A. 加新面经

> 3 种来源 → 同一个 LLM 模板处理。

### A1. 我刚面完，有录音转录文本

```
1. 拿到录音转录文本（讯飞 / Whisper / 任意 STT）
2. 在 Claude Code 里说：
   "用 [[模板/录音转面经]] 整理这段我自己的面试记录"
   公司：字节
   BU：财经
   轮次：一面
   日期：2026-05-15
   结果：挂
   原文：<贴录音转录>
3. Claude 自动生成 资料/面经/字节/财经/字节财经一面_2026-05-15.md
   含完整 frontmatter + 双链回主题文章
4. 跑 /wiki-lint 验证
5. 在对应公司画像 ([[公司画像/字节]]) 顶部加一行：
   - 一行 wikilink + 一句话主旨（例：`- 字节财经一面_2026-05-15 —— 这场考了 ConcurrentHashMap、范式、Token`）
```

### A2. 从牛客 / 朋友圈 copy 别人的面经

跟 A1 一样，只是换关键参数：
```
"用 [[模板/录音转面经]] 整理这段网上转载的面经"
公司：字节
BU：财经（不知道写"未知"）
轮次：一面
日期：约 2024-08（不知道写"未知"）
结果：未知
来源：网上转载
原文：<贴 copy 的内容>
```

### A3. 自己手敲（少见）

打开 [[模板/新面经原文]]，全选复制 → 新建文件粘贴 → 替换占位符。

### A 后续复盘

先列当时的回答，等本人判断后再打磨。确认后的完整通用答案写回技术主题，完整项目答案写回项目追问；面经中保留本次复盘摘要、日期和定稿链接。已有历史改进稿保留，不把它冒充新的现场原话。

### A 收尾（无论哪种来源）

公司名称统一归档：**TikTok / TT 归入字节**，`company` 填 `字节`；`bu` 保留 `TikTok-SRE`、`TikTok-Search-Ads` 等具体方向。现有 TikTok 面经放在 `资料/面经/字节/TikTok/`，公司画像统一使用 [[公司画像/字节]]。

- [ ] 文件放 `资料/面经/<公司>/<BU>/<标题>.md`（BU 不知道就放 `资料/面经/<公司>/`）
- [ ] frontmatter 含：`company` `bu` `round` `date` `verdict`（通过/挂/未知）`source`（我面试/网上转载）`tags`（3-8 个）
- [ ] 公司画像加一行 wikilink
- [ ] 按「索引、日志与搜索」维护总索引
- [ ] 跑 `/wiki-lint`
- [ ] 在日志末尾追加入库记录和实际检查结果

## B. 找面经 / 看公司爱考什么

### B1. 我下周可能要面 X 公司

```
Cmd+O → 输 "公司画像/X" 或 X 的名字
↓
打开公司画像 (e.g. [[公司画像/字节]])
↓
看：
  · 概览（方向 / 难度 / 一句话）
  · 考察重点（出现次数排序）
  · 真题摘录（直接背）
  · 复习清单双链 → 跳到 [[Java并发集合]] 等八股
```

### B2. 想知道整体趋势

打开 [[dashboard/面试历史]]：
- 近一年所有面经的时间线 + 通过状态
- 按公司分组的场数

打开 [[dashboard/公司爱考什么]]：
- 每家公司高频 tag
- 全市场最热考点排行

> 数据是 Dataview 从 frontmatter 自动算的，加完 frontmatter 就自动出现。

### B3. 想找特定考点出处

```
Cmd+Shift+F → 全文搜 "MVCC" / "Lua" / "ConcurrentHashMap"
↓
选最相关的 [[Java并发集合]] / [[MySQL-MVCC与隔离级别]] 等主题文章
↓
文章末尾"真题来源"列出每家公司哪场问过
```

## D. 收学习材料 / 维护技术主题

### D1. 先判断内容性质

- 外部文章、录音摘录、历史讨论与参考手册：放 `资料/学习材料/<分类>/`，保留出处和原有日期。
- 第三方项目课程、数据库脚本等学习候选：放 `资料/项目参考/`。
- 已核验、已写成完整知识文章：直接归入 `wiki/技术主题/`，不另造一份“压缩版”。

### D2. 再查现有主题

先读 [[index]] 和 [[索引/主题]]。同一主题已存在时，把新增且不重复的内容补进主专题；问答页只保留题目、短答、项目差异和具体章节链接。新增专题从 [[模板/新主题文章]] 起步，按“定义、解决的问题、机制、面试答法”组织，保留来源与核验日期。

一个考点在多家公司反复出现时，优先整理成独立专题。Agent 产品、框架或接口的易变事实按 `AGENTS.md` 要求先查最新源；归档旧材料本身不表示其技术结论已经重新验证。

### D3. 收尾

- [ ] 原始资料与独有内容保留；完整解释有明确维护位置
- [ ] 总索引、主题索引和相关公司画像同步更新
- [ ] 运行 `python3 wiki/scripts/lint_wiki.py`
- [ ] 追加维护记录和实际检查结果

## 常见问题

**Q: dashboard 表格全空？**
A: 1) 装 Dataview；2) 已有面经文件没 frontmatter——用 [[模板/录音转面经]] 重新整理一遍，或手动加 yaml。

**Q: 加完文件双链不工作？**
A: 跑 `/wiki-lint` 看具体哪里 broken。一般是路径写错或者拼写不一致。

**Q: 简历 PDF 在哪？**
A: 仓库根 `简历/` 是 symlink → `/Users/ha/Documents/投递文件/`，按 ISO 日期命名。**不进 git**。

**Q: hook 提醒了"记得增量刷新 wiki"是什么意思？**
A: 修改资料目录里的 Markdown 时，`.claude/hooks/wiki_refresh_hint.sh` 会提醒你顺便更新 wiki 的相关公司画像、主题、总索引和日志。

**Q: 算法在哪？**
A: 不在这个仓库。算法有专门的仓库。
