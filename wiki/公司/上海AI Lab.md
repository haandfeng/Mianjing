# 上海AI Lab

## 概览
- 方向：**后训练数据合成/筛选**——基座模型后训练数据的生产团队（不局限于合成，也做数据筛选）
- 难度：项目深挖（agent 方向重点考）+ 一道真实 AI-coding 系统设计实操，**零传统八股**
- 一句话画像：前半段考项目里的 agent 工程判断力（尤其 memory / harness / 多 agent 设计），后半段全程用 AI 协作写代码，**考的是能不能对 AI 生成的代码 take responsibility，不是编码速度**

## 考察重点（按出现次数排序）
1. **Agent 项目里的验证/评测方法论** —— 不只问"你做了什么"，追问"你怎么知道这个改动真的有效"（谷歌 Memory 插件 A/B 测试维度、样本量、资源受限下的取舍）
2. **成功轨迹 vs 失败轨迹的数据价值** —— 面试官主动讲解的后训练数据领域知识：失败原因发散、成功路径收敛，所以后训练数据生产更看重"能不能采出一条成功轨迹"，不是"从失败里学教训"
3. **Agent 框架选型判断力** —— 不是问"你用过什么框架"，而是让你在追问压力下总结出"旧范式（workflow 编排，专家先验）vs 新范式（agent loop，自由探索）"的选型判据，考的是能不能给出**可验证的判据**而不是形容词
4. **AI-coding 实操 + 交付责任心** —— 真实开一个 agent 编程环境，跟 AI 协作完成一个系统设计题，面试官全程观察协作方式，最后连环追问"可以交付了吗"，逼你说清完整交付链路（需求→选型→设计→review→测试→文档）并在最后一刻真正说 yes

## 真题摘录（值得背的）

> **一定要成功轨迹吗？失败轨迹不能用吗？** 出处 [[公司/上海AI Lab/后训练数据/上海AI Lab后训练数据一面_2026-07-31]]
> 面试官口径：错误的原因千千万，堵住一条模型可能踩另一条，很难归纳出「为什么总错」；对的路径基本只有一条。所以一道题试 20-30 次，只要出现一条成功轨迹就行。
> **这套做法的正式名字是 rejection sampling fine-tuning（RFT）**，同族有 STaR / Expert Iteration / ReST^EM。工业锚点：Llama 2 的 RLHF V1–V4 全程只用 RFT，V5 才上 PPO；DeepSeek-R1 第三阶段拒绝采样收了 60 万条。
> **最强的一句串联：pass@k 就是数据良率。** 一道题 pass@k=0 就产不出任何 SFT 数据，「harness 决定能不能揉出正轨迹」翻成指标就是「harness 直接抬 pass@k」。**反向加分点：pass@k=1 的题同样是废题**（RL 梯度为 0），真正的工程约束是把难度卡在 pass@k 既不是 0 也不是 1 的带里。
> **失败轨迹怎么用**（最强接话点）：配对成偏好对做 DPO（ETO, ACL 2024）／给 PRM 提供步骤级监督（Math-Shepherd）／hindsight relabeling。**失败轨迹不是没用，是不能单独用。**

> **旧范式（LangChain/LangGraph）和新范式（Claude Code/Codex）的核心区别是什么？** 出处同上（**被连问 6 轮没答出，面试官最后自己给了答案**）
> **有官方口径**：Anthropic《Building Effective Agents》—— workflow 是 LLM 和工具通过 **predefined code paths** 被编排；agent 是模型**动态指挥自己的流程**。判据一句话：**编排权归谁**。**关键词不是 loop 是「自主」**——LangGraph 也有循环，但转移函数是人写的条件边。完整对比见 [[Agent设计模式与MCP]] §「旧范式 vs 新范式」。

> **O(1) 按索引返回 TXT 文件某一行的库设计，可以交付了吗？** 出处同上
> 交付链路：明确需求 → 技术选型 → 算法设计 → **code review**（类怎么划、依赖关系、函数契约，不只是功能对不对）→ 测试（功能性 + 边界 + 压力）→ 文档 + 已知限制 → 小流量试跑。
> **面试官逐字揭底：「我主要考察面试者能不能对自己的代码 take responsibility……前面一直在质疑你，最后一刻你真的完成的时候，你能不能做到 say yes。」**
> **这题唯一的坑就一个字：大。** 需求「O(1) 返回某一行」本身就暗示大文件——小文件 `readlines()[i]` 就完了，不需要做成一个库。**拿到题先问规模量级。**

## 🔴 复盘教训（面这家之前先看这一段）

**根因不是「把判断权交给面试官」（那只是语言表现），是——持有正确的材料，但从不对材料署名下判断，等着别人告诉你哪块材料有用。** 详见面经 §0。

候选人自己在 57:46 给了最准的解释：「因为平时我工作都是**自己 own 一个 project**……就是自己把这个功能 ok 了。」——**这把「不 review」从态度问题改判成了经验缺口**：从来没有过「把东西交给别人用、并向别人证明它够好」这一步，而这场从头到尾测的就是这一步。

**贴显示器：知识不是交付物，判断才是。每个回答的第一句必须由我签字：「我判断 X，依据是 Y」。**
自检：**「这句话只有我能说吗？」**——换任何看过同样资料的人都能说出来，那它是知识不是判断，重说。

三条最该带走的：
1. **被质疑或被追问时，第一句必须是带主语「我」的判断句，说完停住。** 三个高频场景背死：被质疑数字 →「我的判据不是条数，是能不能稳定区分两版方案」；被问 A/B 区别 →「核心区别是编排权归谁」；被问能否交付 →「可以，交付三样：包、文档、已知限制清单。这个范围内我签字。」
2. **屏幕上敲第一行字之前，必须已经问出一个「答案会换掉一种数据结构」的问题。问不出来就不许动手。**（文件多大／多少行／QPS／数据会不会变 = 主菜；索引 0-based／换行符要不要剥 = 配菜，不能只有配菜）
3. **反问环节照读会前预写的清单**（必问 2 + 加分 2 + 备用 1）。中途冒出的好奇心一律记纸上不当场问，**唯一例外是需求澄清**。会前 30 分钟做最低限度调研——**说不出这家机构任何一个具体项目名就不许进场**（这家可提 InternBootcamp）。
