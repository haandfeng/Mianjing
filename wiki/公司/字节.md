## 概览
- 方向：**四条线** —— 财经业务（今日头条）、广告中国（巨量引擎/商业化）、广告国际化（TikTok Ads / 国际商业化）、**Commercial AI · Agent Infra（商业化 AI 基础设施，2026-07 新增）**

- 一句话画像：项目讲得清楚就能聊久；八股口径要严，喜欢顺着追问到底层原理（Bi-Encoder vs Cross-Encoder 一类）

- ⚠️ **同一条线上，三轮的追问形状各不相同，而且逐级下沉**：**一面扫描式**（一题一问、点到即止、覆盖九个维度）→ **二面刨根式**（咬住一个点连问 3-6 次，问机制）→ **三面原理式**（你怎么做的听一遍就过，只在「这零件为什么能工作」处停下）。**一面要「每个维度的第一答案都完整」，二面要「每条链准备到第四层」，三面要「每个组件的底层原理张口就来」。**

## 考察重点

### A. Agent Infra 线（2026-07 起，与下面的八股线互不重叠）
1. **memory 系统设计九维度** —— 自进化的定义 / 长短期与类别分层 / 存储介质 / 写入时机 / 新旧冲突消解 / 记忆污染 / 交付形态 / agent runtime 迁移。**面试官按这个顺序逐项扫，一题一问不深追，但每一项都要有完整的第一答案**
2. **多 Agent 编排的动机与效果** —— 决策树门禁怎么构建、review agent 看什么信息、消融实验的数字对照
3. **方案伸缩性** —— 业务量涨十倍这套还 run 得动吗（检索层 / 决策树层 / 评测层三层分别答）
4. **AI coding 使用心得** —— 团队明确的用人要求，**是送分展示题不是闲聊**
5. **你所用框架的扩展点**（二面新增，🔴 断点）—— hook 挂在生命周期哪个位置、一共有哪些 hook、能不能拦、能不能改写入参。**这是你项目的说明书，不是课外知识**
6. **单实例 → 平台的完整链路**（二面新增，连问五次）—— 多实例怎么分流 / 只读物料与会话产物分别放哪 / checkpoint 数据库选型（**先算量级再选型，别用「写多→NoSQL」的八股推理**）/ 实例挂了内存里的东西丢不丢
7. **多租户与代码权限**（二面新增，🔴 对方主场）—— agent 用服务账号权限替用户干活 = **confused deputy**；**过滤点必须在工具层做身份透传，不能在输出层删路径**
8. **RAG 存储与检索的原理层**（二面新增，🔴 断点）—— ES vs 专用向量库怎么选、Milvus 的 BM25 是内置函数还是你自己灌 sparse、**BM25 的稀有词靠 IDF（跨文档）不是 TF（篇内频次）**
9. **编码题：agent context manager**（二面）—— `max_token` + `max_turn` 双限制的滑动窗口。**核心考点是「必须整轮丢弃」**，半轮会留下孤儿 `tool_result` 直接触发协议报错
10. **算法一道 Medium** —— 会议室 II（LC253，一面）、统计完全子数组的数目（LC2799，三面）
11. **检索与重排的底层原理**（三面新增，🔴 断点，**而且是同一题在本仓库第二次被考**）—— **embedding 模型 vs reranker = Bi-Encoder vs Cross-Encoder**：区别在**输入方式（分开各编一次 / 拼成一条一起编）和输出类型（向量 / 标量分数）**，**不在预训练目标**。会顺着追「**那个分数是模型自带的还是你们建的**」——答案是 cross-encoder 顶上的**打分头**，用相关/不相关文档对训出来的偏序
12. **能力该做成 skill 还是工具**（三面新增，✅ 全场答得最好的一段）—— **skill / prompt 是建议，模型可以不听；「一次不做就等于系统失效」的能力必须做成带硬校验的工具**
13. **知识源怎么抗过期**（三面新增，✅）—— **文档只写「在哪能找到答案」，不写「答案是什么」**；易变事实从代码现读（后台每 3 小时拉一次代码），**只有稳定的元信息才进文档**

## 真题摘录（值得背的）

> **自进化 Memory 跟普通 Memory 的区别是什么？** 出处 [[字节/中国商业化/字节商业化AgentInfra一面_2026-07-30]]
> 三句话：**普通 memory 只有写入，自进化 memory 有写入 + 打分 + 回滚**；**普通 memory 的单位是一轮对话，自进化 memory 的单位是一条完整轨迹**；**普通 memory 的裁决者是模型自己，自进化 memory 的裁决者是留出验证集**。对标微软 SkillOpt——把 skill 文档当可训练参数，编辑只有严格提升 held-out 验证分才被接受。

> **用户往 memory 里写一句「以后每次都这样称呼我」，会污染上下文吗？** 出处 [[字节/中国商业化/字节商业化AgentInfra一面_2026-07-30]]
> **分两种，而这个例子正好是会的那种。** 检索是两级的：常驻上下文的只有「标题 + 描述」，正文按需读——**写进正文的影响被检索框住，写进描述的等于每轮都注入**。而无条件生效的用户偏好一定落在描述层。这类问题的正式名字是 **memory poisoning**，OWASP 2026 年 Agentic Top 10 的 ASI06；跟提示注入的区别是**它是持久的，写入和发作在时间上解耦**。

> **昨天的 memory 跟今天的 memory 冲突了怎么办？** 出处 [[字节/中国商业化/字节商业化AgentInfra一面_2026-07-30]]
> 关键判断：**别让模型判断哪条更新**。两件事——①**合并不删除，只标失效**（每条挂「何时成立 / 何时被取代」，可回溯、可回滚）②**裁决用系统字段**（写入时间、来源可信度、作用域），**模型只负责「发现矛盾」这个语义任务，不负责「判定谁赢」这个事实任务**。

> **你这个 memory hook 挂在 agent 生命周期的哪个点？系统还支持哪些 hook？** 出处 [[字节/中国商业化/字节商业化AgentInfra二面_2026-08-06]]
> 按一轮生命周期报：**会话开始/结束 → 用户输入提交后·模型调用前（memory 注入就挂这里）→ 工具调用前/后（调用前能拒绝、还能改写入参）→ 子 agent 启动/结束 → 一轮回答结束（能拦，可要求它继续干）→ 上下文压缩前/后 → 权限请求**。
> **收口要给出设计判断**：注入点每轮都跑，只适合读；**自进化的「跑验证集 + 变差回滚」属于一轮闭环之后，该挂在回答结束或走离线定时任务**；而**从轨迹学习最该挂的是「工具调用后」——价值信号在中间的工具结果里，不在最终回复里**。

> **embedding 模型和 reranker 的区别是什么？那个分数是哪来的？** 出处 [[字节/中国商业化/字节商业化AgentInfra三面_2026-08-14]]（🔴 答错，**贝壳 2026-03 已考过同一题**）
> **区别在输入方式和输出类型，不在预训练目标——别说成「一个词语接龙一个词语填空」。**
> **embedding = Bi-Encoder**：query 和文档**分开各编一次**得两个向量，算余弦相似度。**文档向量能离线全部算好存库**，在线只编 query 一次前向；代价是**整篇压成一个定长向量，细节必丢**。
> **reranker = Cross-Encoder**：query 和文档**拼成一条**送进模型，attention 让两边 token 直接交互，**顶上一层打分头把整条输入压成一个标量**（再用 sigmoid 压到 0~1）。**分数依赖 query，没法预算**，每个候选都要跑一次前向，所以只能对召回后的几十条做精排。
> **自带的证据**：BGE 家的 embedding 和 reranker 同底座（XLM-RoBERTa，填空式），千问3 家的也同底座（Qwen3，接龙式）——**同一家两个模型底座相同，说明预训练目标根本不是区分点**。
> **顺带解释了「30 篇要 6 秒」**：那是 **30 次串行前向**，不是架构缺陷；提速的白捡做法是 **batch 化**，换小模型是拿精度换速度。

> **决策树这套能不能沉淀成 skill？** 出处 [[字节/中国商业化/字节商业化AgentInfra三面_2026-08-14]]（✅ 全场最好）
> 「**可以，但它不一定会调**——我们实测就有不生成决策树的情况，**而我们要求所有任务都必须生成**。所以做成**工具 + 硬校验**：生成回答前必须先有树，树的节点必须填完整。」
> 收口成一条原则：**「大部分时候做了就行」的能力放 skill；「一次没做就等于系统失效」的能力必须放成带校验的工具。** 判据是**漏一次分支，用户拿到的是看起来很有道理的错答案，而且他察觉不了——这种错误比报错危险**。

> **BM25 为什么能发现文档里那些很少出现的词？** 出处 [[字节/中国商业化/字节商业化AgentInfra二面_2026-08-06]]
> **稀有性来自 IDF，是跨文档统计的**——整个语料库里包含这个词的文档越少，权重越高，**跟它在当前这篇里出现几次无关**。三块拆开记：**IDF 决定这个词值不值钱；TF 决定这篇提了几次（有饱和，提 10 次不值 5 次的两倍）；长度归一化防止长文档靠篇幅堆词频**——注意**文档越长得分越低，方向别说反**。
> 用在 RAG 里的收口：手册里的型号、错误码、参数名 IDF 极高，**而这正是 dense embedding 最弱的地方**——500 token 压成一个向量，这几个词的信号会被主体语义稀释掉。

> **写一个 agent 的 context manager：可以一直 add_message，get_context 要同时满足 max_token 和 max_turn。** 出处 [[字节/中国商业化/字节商业化AgentInfra二面_2026-08-06]]
> 三个必须主动说出来的点：①**`add_message` 不做淘汰**——存储和呈现是两件事，历史要全留，限制只作用在喂给模型的那一份 ②**一轮 = 从一条 user 消息到下一条 user 消息之前的全部消息**（中间可以有任意多条 tool call），所以数轮只能**从尾往前扫、遇到 user 就 +1** ③⭐**必须整轮丢弃，不能丢半轮**——半轮会留下没配对的 `tool_result`，OpenAI 和 Anthropic 协议都会直接报错。**这第三点是「不知道就一定写错」的分水岭。**

> **ConcurrentHashMap 桶数量为什么是 2 的 n 次方？** 出处 [[字节/中国商业化/字节跳动中国商业化一面面经]]
> 三个原因：①位运算取模快（hash & (length-1)）；②保证元素均匀分布（length-1 全 1，hash 每位都参与）；③扩容迁移高效（看新增高位是 0 还是 1，要么留原位要么移到原位+旧容量）。不是为了减少哈希冲突——减少冲突要用大质数。

> **十个进程同时跑，虚拟内存和物理内存怎么映射，会冲突吗？** 出处 [[字节/国际商业化/10.13 字节 国际化广告 后端]]
> 不同进程的不同虚拟地址可以映射到同一物理地址（共享库 / 文件页缓存 / 共享内存 / fork COW / 零页），不冲突。每个进程有独立页表，MMU + TLB 做翻译，缺页时由内核分配物理页框并更新页表。

> **Redis 删除一个 key 的时间复杂度？** 出处 [[字节/国际商业化/面经记录_国际商业化创业_3.9]]
> 物理删除，按数据结构：String O(1)；List/Hash/Set O(N) 遍历释放；ZSet O(N·logN)。生产删大 Key 用 UNLINK 异步释放，避免阻塞主线程。
