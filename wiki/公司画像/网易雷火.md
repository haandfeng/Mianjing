## 本场考察重点

1. **RAG 选型与证据链**
   - 为什么换向量模型？
   - 为什么从 Elasticsearch 迁移到 Milvus？
   - 已有多语言向量模型，为什么还要查询改写？
   - 多路召回后，RRF（reciprocal rank fusion，倒数排名融合）和重排模型分别解决什么？

2. **评测口径**
   - 正确性、相关性、有依据性分别怎么测？
   - 大语言模型 judge 与人工标注怎么校准？
   - 面试官会注意指标名称和数字是否前后一致。

3. **Agent 方案能否自洽**
   - 决策树门禁能提高分支覆盖率，但不能保证答案一定正确。
   - 代码能确认当前实现，但不能替代 PRD（product requirements document，产品需求文档）里的业务语义。
   - 基础模型认识「玩法」这个词，不等于知道公司内部玩法规则。

4. **模型网关工程**
   - 多厂商消息和工具调用协议怎么统一？
   - 提示词缓存和不透明推理状态怎么保留？
   - 如何用 trace（链路追踪记录）定位一次 Agent 调用的模型、工具、延迟和错误？

5. **自研系统与通用编程 Agent 的边界**
   - 通用编程 Agent 负责代码、终端和测试。
   - 内部答疑 Agent 还需要业务知识、权限、决策树门禁和专用评测。
   - 外部产品的实现与许可证状态必须先查官方来源再回答。

6. **个人方向**
   - 是否有真实 Agent 开发经验。
   - 是否理解大语言模型的能力边界。
   - 是否有能与算法同学协作的 AI 算法基础。

## 真题摘录

> **已经用了多语言向量模型，为什么还要翻译或改写查询？**  
> 开口先分清：多语言向量模型解决跨语言语义对齐，查询改写解决型号、缩写、内部术语和同义表达。原查询与改写查询一起召回，是否保留这一步由消融实验决定。详见 [[资料/面经/网易雷火/游戏AI中台/网易雷火游戏Agent面试_2026-08-26#4. 已经用了多语言向量模型，为什么还要做查询改写或翻译？]]

> **RRF 和 reranker 为什么都要？**  
> RRF 只按多路排名做融合，解决不同检索分数不可直接比较；reranker 同时读取查询与候选文档，解决前几名的精度。固定链路：多路召回 → RRF 融合 → reranker 重排 → top N 生成。详见 [[资料/面经/网易雷火/游戏AI中台/网易雷火游戏Agent面试_2026-08-26#5. 为什么已经做了多路检索，还需要 RRF 和 reranker？]]

> **决策树如何保证所有分支？**  
> 不能承诺保证。代码和配置只能枚举已实现分支，PRD、设计文档和历史问答补业务语义，最终仍要靠回归集验收。详见 [[资料/面经/网易雷火/游戏AI中台/网易雷火游戏Agent面试_2026-08-26#10. 决策树怎么保证分支完整？需要业务知识吗？]]

> **为什么自己做模型网关？**  
> 统一入口只是第一层；还要适配消息、工具调用、流式事件、缓存、不透明推理状态和链路追踪。详见 [[资料/面经/网易雷火/游戏AI中台/网易雷火游戏Agent面试_2026-08-26#12. 为什么要做内部模型网关？]]

> **自研 Agent 与 Claude Code、Codex 的差异？**  
> 从任务对象、知识来源、权限和评测比较，不只说「垂直与通用」。Codex 当前是 Apache-2.0；Claude Code 仓库公开可见，但许可证保留所有权利。详见 [[资料/面经/网易雷火/游戏AI中台/网易雷火游戏Agent面试_2026-08-26#14. 自研 Agent 与 Claude Code、Codex 有什么区别？]]

## 这家公司面试前的准备顺序

1. 固定项目数字与指标名称，避免 86 / 87、准确率 / 平均得分混用。
2. 能在 30 秒内讲清完整 RAG 链路及每一步解决的问题。
3. 准备一个 Agent 失败案例：漏分支、张冠李戴、检索不到或协议状态丢失。
4. 准备模型网关的一次完整调用链，从业务请求到模型、工具、缓存和 trace。
5. 对 Claude Code、Codex 等快速变化的 Agent 产品，面试前重新查官方文档、源码和近期社区分析。
