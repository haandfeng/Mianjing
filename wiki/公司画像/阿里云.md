## Agent Infra / AI 应用工程师（ATH）

### 考察重点

1. **项目证据与实验设计** —— 两场面试都追 Memory 的评测与收益；二面新增数据清洗、难度分类、新题探测、Wiki 与 Memory 的效果区分。
2. **评测裁决者是否可信** —— 不接受「把温度设为 0」作为可信度证明，要说明人工标注如何校准模型判卷。
3. **工具调用能否规模化** —— 从工具定义、参数校验和调用结果关联，追到 1000 个工具时如何先筛选再按需加载。
4. **全栈 Agent 链路** —— 前端流式显示、服务端会话隔离、多工具结果、Subagent 生命周期、断线恢复和链路追踪要连起来。
5. **资源与延迟治理** —— 多会话、单活跃会话、1GB PDF 和 5–8 分钟延迟都要求先定位资源花在哪里，再选持久化、压缩、并行或模型路由。
6. **Runtime Coding** —— 补充笔试直接要求写模型—工具循环；重点是数据结构、History、单工具异常隔离和确定性退出，不是只把工具调用通。
7. **AI Coding 验收** —— 业务文档只能保存上下文，最终仍要由人定义需求与关键测试，并用真实集成链路验收。
8. **字节业务问答的设计取舍** —— 二面连续追为什么选决策树、为什么独立审核、意见不一致怎么处理，以及 56 → 87 的主要改动。
9. **缓存与上下文管理的实际效果** —— 二面追缓存 token 占比、缓存原理、不同模型的缓存差异，以及长工具结果保存和对话压缩的效果。

### 真题摘录

> **为什么不用历史数据直接优化固定 Prompt / Skill，而要做 Memory？** 出处 [[资料/面经/阿里云/Agent Infra/阿里云Agent Infra面试_2026-09-09#6. 为什么不直接用历史数据优化 Prompt / Skill，而要用 Memory？]]
> 稳定、全局的规则优先沉淀成有版本的 Skill；持续变化、带用户或团队作用域的状态才进入 Memory。固定 Skill 做强基线，Memory 只有在同一留出测试集上带来净收益才接入。

> **有 1000 个工具，怎么保证模型有效调用？** 出处 [[资料/面经/阿里云/Agent Infra/阿里云Agent Infra面试_2026-09-09#11. 有 1000 个工具，怎么保证有效调用？]]
> 先按用户权限和租户过滤，再检索当前问题相关的候选工具，只加载少量完整定义；Runtime 校验参数和权限，用调用标识符关联多个结果。

> **单个活跃 Session 也会撑爆内存，怎么处理？** 出处 [[资料/面经/阿里云/Agent Infra/阿里云Agent Infra面试_2026-09-09#13. 服务器内存持续升高，甚至单个 Session 超内存，怎么处理？]]
> 先区分对象已无用但未释放、闲置会话未淘汰、单活跃会话本身过大；分别检查引用、设置会话上限，或外置大工具结果并压缩早期上下文。模型上下文变短不等于服务进程已经释放内存。

> **现场实现一个支持多工具、多轮和异常恢复的 Agent Runtime。** 出处 [[资料/面经/阿里云/Agent Infra/阿里云ATH Agent Infra补充笔试_2026-09-16#8. 复盘后的最小实现骨架]]
> History 保存用户消息、模型工具请求和每个工具结果；每个工具独立捕获异常并带调用标识符写回；模型不再请求工具时正常退出，达到最大模型轮次时硬退出。

## 消息商业化 / RocketMQ

### 考察重点

1. **大规模数据迁移方案设计** —— 分块全量、双写、影子读、灰度切流和可观测性；监控比代码更重要。
2. **RabbitMQ 不丢不漏全链路** —— 生产者 Confirm、Broker 持久化、消费者手动 ACK、本地消息表和死信队列。
3. **CDC 增量同步与同用户有序** —— Kafka 用 userId 做 partition key；RabbitMQ 用 Consistent Hash Exchange 实现等效路由。
4. **支付分布式一致性** —— 本地消息表、独立对账、TCC 和最大努力通知组合使用。
5. **RAG ETL 流水线扩容** —— MQ 解耦解析、Embedding 和落库，各阶段独立扩容。
6. **积分对账业务维度** —— 流水表净变化、按主键抽样和唯一流水 ID 幂等。
