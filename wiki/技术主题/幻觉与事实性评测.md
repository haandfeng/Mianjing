# 幻觉与事实性评测

> 幻觉**不是 bug，是训练目标的产物**。所以「怎么解决」这个问题问错了方向——工程上能做的是**把不确定变成可观测、可判定的信号**。
> 面试考两件事：**① 原理你讲不讲得清两段**（预训练 + 评测激励）**② 忠实度和事实度你分不分得开**。

## ① 技术定义

**幻觉** = 模型输出了**流畅、自信、但没有依据或与事实不符**的内容。

三个词要先分清，混着说是最常见的减分点：

| 词 | 比对的对象 | 需要什么 | 能不能自动跑 |
|---|---|---|---|
| **忠实度**（faithfulness / groundedness） | **你给它的材料** | 只要有检索上下文 | ✅ 能，且**不需要标准答案**（reference-free） |
| **事实度**（factuality） | **世界真相** | 需要外部可信源或人标 | ❌ 一般只能抽样离线跑 |
| **相关性**（answer relevancy） | **用户的问题** | 只要有问题和回答 | ✅ 能 |

> 🔑 **忠实度和事实度会双向背离，这个例子必须能张口就来：**
> - 材料本身是错的，模型**忠实地**照抄 → **忠实度满分，事实度 0**
> - 模型凭参数里的记忆答对了，但材料里没写 → **事实度满分，忠实度低**

---

## ② 不管它会怎样

1. **错得很自信，所以人 review 不出来。** 幻觉产出的不是乱码，是「读起来最像对的那个答案」——这正好是人眼最容易放过的。
2. **静默退化。** 换模型版本、prompt 改一行、知识库更新，准确率掉了没有任何报错。**没有评测就等于没有信号。**
3. **在 Agent 里会被放大。** 单轮答错是一个错答案；多轮里第 3 步编了个不存在的字段名，后面 20 轮全建立在这个字段上。

## ③ 机制

### 3.1 为什么必然有幻觉——两段式（这是「原理」题的完整答案）

**第一段：预训练目标里根本没有「真」这一项。**

语言模型优化的是**似然**——

> `似然（likelihood）`：给定前面的文本，模型认为下一个词该是某个具体词的概率。训练就是把语料里真实出现的那个词的概率往上抬。

注意这里面没有任何一项是「这句话是不是真的」。OpenAI 2025 年那篇 *Why Language Models Hallucinate*（Kalai / Nachum / Vempala / Zhang）把它**归约成一个二分类问题**：如果模型没能力把「错误陈述」和「事实陈述」分开，那么在自然的统计压力下，预训练模型**必然**产生幻觉。

**尤其是训练语料里只出现过一次的事实**（论文里叫 **singleton**，比如某个不出名的人的生日）——模型没有足够信号学会它，只能按语言规律猜一个**看起来对**的。

**第二段：为什么后训练之后还在——这段才是那篇论文的新意，也是拿分点。**

> **因为评测在奖励猜测。**

绝大多数评测集是 0/1 打分：答错 0 分，答「不知道」也是 0 分。那么**猜是严格占优策略**——猜对有分，猜错不比弃答更亏。模型被优化成一个好的应试者，而好的应试者遇到不会的就是要蒙。论文对主流评测集做了元评估，确认**多数评测确实偏向奖励猜测**。

**所以修法在评分规则上**：对错误答案扣分、对「不确定」给部分分，让**校准**比装懂更划算。

> `校准（calibration）`：模型说「我有 70% 把握」的那批回答，实际正确率就该接近 70%。
> 论文一个反直觉的结论：**做到校准，比做到准确要容易得多**（计算意义上）。

**第三段（补一句，接上下文管理）：** 材料就在上下文里它也可能不用——**注意力被稀释**。上下文越长越明显，所以压缩不只省钱，是提准确率的手段。见 [[Agent上下文压缩链路]]。

> 📌 出处：[Why Language Models Hallucinate](https://arxiv.org/abs/2509.04664)（arXiv 2509.04664，2025-09）+ [OpenAI 官方解读](https://openai.com/index/why-language-models-hallucinate/) ・ **官方论文 + 官方博客双确认** ・ 查证于 2026-08-04

### 3.2 工程上怎么办——排序原则

**先死保忠实度，事实度靠语料治理。**

理由很硬：忠实度是**我能控制的**（材料是我给的，比对可以自动化，不用标注）；事实度取决于知识库本身对不对，那是**数据治理问题不是模型问题**，用模型手段治标不治本。

```mermaid
flowchart LR
    Q[用户问题] --> R[检索侧]
    R --> G[生成侧]
    G --> V[生成后校验]
    V --> A[答案]
    V -.事实错误则打回.-> G
```

| 段 | 手段 |
|---|---|
| **检索侧** | 混合检索 + rerank 提高「材料本身对」的概率；**召回不到就拒答**——宁可回「知识库里没有」也不给自信的错答案 |
| **生成侧** | 强制引用（每个结论挂来源 ID）；结构化输出；**把「无法从材料中确定」列为一个合法输出** |
| **生成后** | **claim 级回验**：把回答拆成一条条原子断言，逐条回材料判有没有支撑，命中比例就是忠实度分数 |

> ⭐ **「给模型一个认输的选项」这条直接对应 3.1 的第二段。** 如果模型没有合法的弃答出口，它一定会编——这跟评测集只有 0/1 打分是同一个机制在起作用。

### 3.3 评测怎么落地

**RAGAS 四个核心指标：**

| 指标 | 问的问题 | 要不要标准答案 |
|---|---|---|
| **faithfulness** | 回答里的断言，材料里撑不撑得住 | ❌ 不要 |
| **answer relevancy** | 回答有没有答到问题上 | ❌ 不要 |
| **context precision** | 召回的材料里有多少是真用得上的 | 要（或用 LLM 判） |
| **context recall** | 该召回的都召回了吗 | ✅ 要 |

**faithfulness 的算法就是 3.2 里的 claim 级回验**：抽 claim → 逐条比对 → 算命中比例。**它是 reference-free 的，所以能挂在线上跑**——这是它比别的指标实用的地方。

**两种判卷方式，别只知道一种：**

| | 自由式 LLM-as-judge | **rubric 踩点** |
|---|---|---|
| 做法 | 让模型自己评「这个答案好不好」 | **专家先定得分点，模型只做匹配** |
| 可靠性 | 低，受措辞和长度影响 | 高，**主观判断被前置到人那里了** |
| 成本 | 低 | 前期要人写 rubric |

> 我在字节用的是后者：**50+ 题专家 rubric 评测集，AI 按得分点判卷**。见 [[追问/字节答疑Bot]] Q5。

### 3.4 一个必须主动说的天花板

> **忠实度指标测不出「材料本身是错的」。** 独立评测也确认了目前没有框架能区分检索到的上下文是对是错。
> **所以忠实度 100% 不等于答案对**，剩下那一半必须靠知识库治理，不能指望评测框架替你兜。

这跟 [[追问/字节答疑Bot]] Q8b 是同一个结论的两种说法：**代码决定精度，文档决定召回；入口错了，事实来源就取错了，agent 依然会给出「有代码依据」的答案，只是依据了错的那段。**

> 📌 RAGAS 指标定义与 reference-free 特性、「没有框架能判断上下文本身对错」：来自社区文档与 2026 年的综述性文章（**二手来源，非官方一手**）・ 查证于 2026-08-04

## ④ 面试怎么说

**幻觉原理（30 秒）**
> 「幻觉不是 bug 是训练目标的产物。预训练优化的是**下一个词的似然**，里面根本没有『这句是不是真的』这一项，所以对语料里只出现过一次的冷门事实，模型只能猜一个像样的。这是第一层。
> 第二层更关键：**后训练之后幻觉还在，是因为评测在奖励猜测**——大部分评测集答错和说不知道都是零分，那猜就是占优策略，模型被训练成一个会蒙题的应试者。OpenAI 那篇论文的主张就是改评分规则，让『校准』比『装懂』更划算。
> 落到工程上：我们改不了预训练，但可以改**我们自己的评测**和**我们给它的上下文**。」

**事实度 / 忠实度（40 秒）**
> 「先分开：**忠实度是回答对不对得上我给它的材料，事实度是对不对得上世界真相。** 两者会双向背离——材料是错的它忠实照抄，忠实度满分事实度零；它凭记忆答对但材料里没有，事实度满分忠实度低。
> 工程上**先死保忠实度**，因为它可控、可自动化、不用标注。三段：检索侧提高材料质量并且**召回不到就拒答**；生成侧强制引用，并且**给模型一个『无法确定』的合法出口**——没有认输的选项它一定会编；生成后做 **claim 级回验**，把回答拆成原子断言逐条回材料查，命中比例就是忠实度。
> **事实度只能靠语料治理 + 抽样人工**，而且要说清一个天花板：**忠实度指标天然测不出材料本身是错的。**」

**预备追问**

| 追问 | 答法 |
|---|---|
| **温度调到 0 不就没幻觉了？** | 不会。温度只影响采样的随机性，**不影响模型知不知道这件事**。它会更稳定地输出同一个错答案 |
| **RAG 是不是就解决了幻觉？** | 不是。RAG 把问题从「模型记不记得」换成「检索准不准 + 它用不用材料」。**材料在上下文里它也可能不用**（注意力稀释），而且材料本身可能是错的 |
| **让模型自己说置信度可信吗？** | 弱信号。模型的自陈置信度**通常过度自信**，除非专门做过校准。更可靠的是外部信号——引用能不能对上、多次采样一不一致 |
| **怎么在线上发现幻觉？** | ① faithfulness 是 reference-free，能实时跑 ② 用户追问率 / 纠正率是隐式信号 ③ 从 trace 里挑低分 case 转成回归评测集（见 [[追问/字节答疑Bot]] Q5） |
| **多模型投票有用吗？** | 对**独立错误**有用，对**同源错误**没用——同模型同训练数据同盲区，审自己的输出会重复同一个错。见 [[追问/字节答疑Bot]] Q2b 的相关性失败 |

## 易错点

1. 🔴 **问「原理」答成「缓解手段」。** 上来就说 RAG / 微调 / prompt 约束，等于没答。原理必须讲两段：预训练的似然目标 + 评测的激励错配。
2. 🔴 **把忠实度和事实度当同义词。** 这题的分水岭就在第一句能不能掰开。
3. 🔴 **说「RAG 解决了幻觉」。** 只是换了失败模式。
4. ⚠️ **只报最终准确率不报消融。** 「56% → 87%」要跟着说清中间那档（+决策树 70% 出头 / +审核 Agent 87%）**以及两者治的是不同的病**，否则听起来像堆方案。
5. ⚠️ **忽略「给模型认输的出口」。** 这是评测激励那套理论最直接的工程推论，说了就显得原理和实践是通的。
