# 测试设计方法论

> 测试用例不是「想」出来的，是从组件模型里**推导**出来的。给组件建模 → 逐个维度攻击 → 每个维度有固定的生成问题。

## 高频问法

- 「具体点，比如说**异常的用例**，你要覆盖的场景」—— 同上（关键区分：异常用例 ≠ 正常操作的边界）

- 「测试相关的要求，你希望重点让 AI 实现哪些测试场景、测试边界？」—— 同上（AI 协作题里同样考这个）

## 答题骨架

### 0. 心法：建模 → 攻击维度

任何组件都可以建模成：

```
输出 = f(输入, 内部状态, 时序, 环境)
```

右边四个自变量 = 四条独立攻击线。**分层不是拍脑袋分的，是从模型推出来的**；维度正交，所以攻破一层的用例天然测不到另一层。

| 层 | 攻击维度 | **生成问题（记这一列）** |
|---|---|---|
| ① 契约 | 输入的合法性 | 「什么输入是这个 API 从没承诺处理的？」 |
| ② 边界 | 值域端点 | 「代码里每个比较符两侧各取什么值？」 |
| ③ 状态序列 | 状态的时间维度 | 「同一个观测状态，能从几条路径到达？」 |
| ④ 并发 | 时序交错 | 「两个操作在哪一步之间被打断会出事？」 |
| ⑤ 资源 | 环境约束 | 「资源不够/超量/依赖失败会怎样？」 |

**纯函数**（无内部状态）→ ③④自动消失，只剩 ①②⑤。分层随组件性质自动裁剪。

### 1. 视角决定上限（微信支付的挂点在这）

| 视角 | 你问自己 | 能找到 | **找不到** |
|---|---|---|---|
| 作者（最弱） | 「我写的逻辑对不对」 | 已写分支里的错 | **漏写的分支** ← 结构性盲区 |
| 规格（合格线） | 「承诺有没有被违反」 | 漏写的分支 ✅ | 规格本身没写清的地方 |
| 攻击者（优秀） | 「我要怎么把它搞崩」 | 没人想过的组合 | — |

> **反面教材**：现场原话「每一个 if else 判断条件我都要过一遍」= 纯作者视角。
> **它的结构性缺陷**：以自己写的代码为地图 → **地图上没画的地方永远走不到**。当天漏的 capacity 校验就是「代码里根本没这条分支」，覆盖率思维必然抓不到。

攻击者视角三个万能套路：**①在最不合时宜的时刻打断它 ②给它刚好越界一点点的值 ③让它连续经历多个状态再回来**。

### 2. ①契约层：列参数表，填「合法域 / 违反样本」

**动作**：方法签名抄下来 → 每个参数一行 → 填三列 → 违反样本那列就是测试数据。

| 参数/返回 | 类型承诺 | 值域承诺 | 违反样本（=测试数据） |
|---|---|---|---|
| `capacity` | int | > 0 | `0` `-1` `3.5` `"5"` `None` `True`(bool 是 int 子类!) `2**63` |
| `pop()` 返回 | (bool, T) | — | T 本身是 `False`/`None` 时怎么区分失败？**二义性** |
| `close()` | — | — | 调两次会怎样？**契约没写** |

对每个参数问三句：**①类型错了会怎样 ②值超范围会怎样 ③文档没说的情况是什么**。

> 第③条最值钱：**「这里题目没说清，我按 X 理解，对吗？」这句话本身就是分数**（微信支付面试官原话认可了 `max_attempts=1` 上的这个做法）。

**契约层为什么能抓到漏写的分支**：它**完全不看代码，只看承诺**——代码没写校验，不妨碍承诺存在。

### 3. ②边界层：圈出每个比较符，两侧各取值

**动作**：拿笔圈出代码里所有比较运算符和数值常量 → 每个圈写下两侧取值 → 每个取值一条断言。

```python
if self._size == self._cap:      # ⭕ → cap-1, cap
if self._size == 0:              # ⭕ → 0, 1
tail = (head + size) % cap       # ⭕ → head+size = cap-1, cap, cap+1
```

**生成问题**：「把 `==` 写成 `>=`、把 `<` 写成 `<=`，行为会在哪个输入上不一样？——那个输入就是测试数据。」专杀 off-by-one，机械可穷举，不靠灵感。

**通用取值套路**：`min-1 → min → mid → max → max+1`
- 容器：空 / 1 个 / 满 / 超一个
- 字符串：空串 / 单字符 / 超长 / 多字节 emoji（编码边界）
- 浮点：0.0 / -0.0 / NaN / ±inf / 精度临界
- 时间：0 / 负 / 恰好相等 / 时钟回拨

### 4. ③状态序列层：找「不能凭空构造、只能走过去」的状态

**核心洞察（想通这句这层就通了）**：

> **②层测的全是「免费的状态」（刚 new 出来那种）；③层测的是「走过去才有的状态」。**

**动作四步：**
1. 列出所有**写方法**（会改状态的）→ 这些是状态机的「边」
2. 列出所有**内部状态变量**及其有意义取值，并标注**能否直接构造**

| 状态变量 | 有意义取值 | 能直接构造吗 |
|---|---|---|
| `size` | 0 / 中间 / cap | ✅ push 几次就行 |
| `head` | **0 / 非 0** | ❌ **必须先 push 再 pop** ← 重点 |
| `closed` | False / True | ✅ |

3. 对每个「不能直接构造」的取值，问**「我怎么走到那儿」**→ 那串操作就是用例脚本
4. **走到之后，把②层的边界断言重跑一遍**

> **③层 = ②层 × 前置状态。** 不是新增用例，是把②层用例在非初始状态下重跑。

**为什么②抓不到 head 类 bug**：②层的用例几乎都从新队列出发，`head` 恒为 0，而 `head=0` 时 `head+size` 与 `(head+size)%cap` **恰好等价**——bug 被完美掩盖。

**三个万能提问：**
1. 「这个内部变量除了初始值还能是什么？我得做什么才能让它变成那样？」
2. 「同一个观测状态（比如『空』），能从几条路走到？」——刚 new 的空 / push 满再 pop 光的空 / close 后 pop 光的空，**②层眼里一样，③层是三个东西**
3. 「做完一件事，有什么该复位却没复位？」

**序列组合不用穷举**，覆盖「相邻两步组合」（transition pair）即可：push→push / push→pop / **pop→push（关键：head 偏移后再写）** / pop→pop / close→push / close→pop / 空→push。7 个组合 7 个用例。

### 5. ④并发层：断言不变量，不断言具体值

三条原则：
1. **Barrier 让线程同时起跑**（放大竞态窗口）
2. **断言不变量**——并发下顺序不确定，但不变量恒成立：`push成功数 == pop出的元素集合`、`计数守恒`、`最终 size 收敛`
3. **多轮重复**（竞态是概率事件）

```python
def test_concurrent_invariants():
    barrier = threading.Barrier(N_PROD + N_CONS)   # 同时起跑
    ...
    assert sorted(popped) == sorted(pushed)        # 不丢不重不串
    assert q._push_ok == len(pushed)               # 计数无竞态
```

### 6. ⑤资源层
下游永久 hang / 内存分配失败 / 重对象拷贝开销 / **拷贝构造抛异常时状态是否一致（C++ 异常安全）** / 长跑计数器溢出。

### 7. 加分项：随机序列对拍（性价比最高）

```python
def test_random_ops_against_reference():
    """拿显然正确的 deque 当影子模型，随机序列对拍，每步查不变量"""
    for seed in range(200):
        rnd = random.Random(seed)
        real, shadow = RingQueue(rnd.randint(1,6)), deque()
        ...  # 随机 push/pop 300 步，逐步比对返回值和 size
```

> 面试话术：「有状态组件我会加一层随机序列对拍——用 deque 当参考实现，失败时用 seed 确定性复现。它能覆盖我手工想不到的路径组合。」

## 易错点 & 追问

- ❌ **把「正常操作的边界」当「异常用例」**：pop 空、push 满是**边界**（代码有定义行为）；**异常用例 = 违反契约、代码没定义行为的输入**（capacity ≤ 0、close 后 push、无锁并发）
- ❌ **防御代码而不是攻击代码**：现场说过「item 没有什么异常的数据」「size 不可能小于 0」——**测试存在的意义就是验证「应该不会」是不是真的不会**
- ❌ **面试官纠正后不转向**：「push 0~5 属于异常用例吗？」是明确点破，当成事实确认题答了。**答错=知识缺口，接不住纠正=实时反馈能力问题**，对没有测试岗、靠 review 互相纠偏的团队是硬伤
  - 战术：先出声承接再重构——「您说得对，我刚才理解有偏差，让我重新组织一下」
- ❌ **流水式列举，没有完备性判据**：想到哪说到哪，结尾只能说「大概是这样」

**临场 30 秒版本：**
> 「我分三步走：**先列契约**——每个参数的合法域、非法输入怎么处理，顺便标出题目没说清的二义性点；**再扫边界**——每个比较条件两侧各取一个值，防 off-by-one；**最后走状态序列**——有些内部状态没法直接构造，只能通过操作走过去，比如 pop 之后 head 就不在 0 了，我要在那个状态下把边界断言重跑一遍。并发和资源再各加一层。」
