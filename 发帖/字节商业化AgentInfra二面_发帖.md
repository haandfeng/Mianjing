## 牛客版

**标题：** 字节提前批 商业化 Agent Infra 二面

**正文（直接粘贴）：**

```
提前批。
没有八股，也没问数据库和 Java，全程围绕项目刨根问底，
外加一道代码题。跟一面那种一题一问的扫描式完全不同：
这场是咬住一个点连着追三到六问，追到你答不出来为止。
结果：过，进三面。

【一、Agent 记忆系统项目相关提问】
1. 先讲一下你这个项目在做什么。
2. 你们必须接入这个统一框架，它是不是有灵活性问题，
   我理解它是一种托管式的。
3. 它跟你自己从零搭的 agent 有什么区别。
4. 你的 memory 是怎么接入的，实现了什么策略。
5. 记忆整合具体是怎么整合的，多条合并成一条吗。
6. 语义相似检索是怎么做的。
7. 检索时拿最近 200 行对话做匹配，这个「后 200 行」
   是什么意思。
8. 所以你们只是把 memory 扔给那个服务，embedding
   选型、分块策略都是它控制的。
9. 检索策略你们可以自定义吗，是语义检索还是关键词
   检索。
10. 介绍一下 hook 机制跟你们的东西怎么结合。
11. 这个 hook 是在 agent 生命周期的哪个点做的扩展。
12. 这个系统还支持其他生命周期的 hook 吗。
13. 评测集是怎么构建出来的。
14. 这个测试集只局限于这一个场景吗，你的自进化
   memory 是只用于这个场景还是通用的。
15. 评测最终就是看数据集那个分吗，有没有别的标准
   评测起来更好。
16. 举一个具体例子：不用你这套精细化 memory 是个
   badcase，用了之后就变好的那种。
17. 所以这套系统是你根据 paper 实现的，还没在线上
   真实 case 里大规模验证，是吧。

【二、多 Agent 问答系统项目相关提问】
1. 讲一下你这个项目具体做的工作。
2. 为什么没有单独一个 agent 去做反问。
3. 你们的主 agent 是哪个。
4. 为什么要采用多 agent 架构，有没有可能用单 agent
   或者 subagent 完成。
5. multi-agent 和 subagent 有什么相同、有什么不同。
6. 什么场景适合用 subagent。
7. 你说 subagent 适合可拆分的任务，那审核这件事
   不是可以独立拆出来吗。
8. 你们这个项目的模型是怎么选型的。
9. 你们 agent 接入了哪些工具，一共多少个。
10. 这些工具跑的脚本都是在本地跑吗。
11. 它是多租户的吗，如果是，每个租户的请求都在
   那个容器本地跑吗。
12. 代码都拉到本地了，会不会出现代码权限问题，
   有没有可能看到其他人的代码。
13. 如果所有代码都在本地，时间长了会不会把本地
   磁盘写满。
14. 简历里那个 HTTPS 连接池的问题是什么。
15. 简历里这个 prompt cache 是指什么。
16. 为什么 prompt cache 能降本增效，底层原理是
   什么。

【三、系统设计（接着上面这个项目追问）】
题面：假设这个 agent 要 scale 到 1-2 万人使用，
整体架构要怎么改。
1. 整体架构应该怎么改。
2. 如果这次打到这个实例、下次打到另一个实例，他
   下载的仓库和过往的会话历史怎么办。
3. 如果要放到一个外置数据库里，这个数据库打算
   用哪个。
4. 为什么是写多读少，什么时候会写、什么时候会读。
5. 你说有些东西存在内存里，如果实例挂了，内存里
   的东西就丢了吗。

【四、RAG 文档检索项目相关提问】
1. RAG 的底层存储当时是怎么选型的。
2. 但是 ES 应该也能支持关键词检索吧。
3. Milvus 也能支持 BM25 吗，是靠 sparse embedding
   支持的，还是它本来就支持。
4. sparse embedding 和 BM25 都能做关键词，它俩有
   什么区别。
5. 什么时候比较适合用 BM25，举个例子。
6. 它为什么能发现这些出现得很少的词。
7. 加了稀疏向量这一路，对效果有多少提升。
8. 那最后还是把这一路保留着吗。
9. Ranker 用的是什么。
10. 原始数据怎么处理，最终入库的流程是什么样的。
11. 是拿全文做一个 embedding 吗。
12. 文档是用什么拆分算法拆的。

【五、代码题：agent 的 context manager】
题面：实现一个 agent 的 context manager，可以一轮
一轮 add_message，消息可能是 system / user /
assistant / tool call；有 max_token 和 max_turn
两个限制；get_context() 返回压缩之后、满足这两个
限制、可以直接喂给大模型的上下文。
1. 你现在这个实现是加不进去就不加了是吧，那我
   最先说的那句话不就丢了吗。
2. 到达最大轮数不是对话结束，它可以一直对话，
   只是上下文最多保留多少轮。
3. 一轮是两条消息吗，如果大模型返回的是 tool
   call 怎么办。

秋招信息差太大了，想找组织一起交流。同投 Agent／大模型岗的友友对对流程

#秋招# #面经# #校招# #字节# #agent# #大模型# #互联网大厂# #提前批#
```
