## 牛客版

**标题：** 快手人才计划 数据平台 Data Agent 二面

**正文（直接粘贴）：**

```
人才计划。
没有八股也没有算法，全程是项目机制追问加通用判断题，最后
一道 AI 辅助 coding 的现场设计题。追问烈度不高，但覆盖的
题量很大。
结果：过。

【一、多 Agent 问答系统项目相关提问】
1. 当时为什么选择做决策编排、也就是决策树这种模式。
2. 剩下那部分答错的 case 是因为什么原因。
3. 什么场景下用「多 agent + 决策树」这套策略比较好，
   不限于你自己的项目，讲讲业界视角。
4. agent 之间的通信（A2A）是怎么设计的。
5. 这种调用方式里遇到过什么复杂问题。
6. 你们的 subagent 机制有什么问题。
7. 另一位候选人的方案是把决策树预编译成 workflow，
   听完这个思路，跟你们现在的方案比怎么样。
8. 这样听下来你们不像典型的树，更像网状。

【二、评测与数据飞轮相关提问】
1. 你做过评测数据飞轮，也做过自演化 memory，跑这类
   自演化方案和飞轮，最关键的点是什么。
2. 评测速度可以靠加机器、建环境解决，但怎么选到优质
   case、case 怎么持续迭代，你们现在有没有比较好的
   办法。
3. 你们的小评测集大概多少条。
4. case 集怎么持续迭代，才能跟上 agent 的发展速度。
5. 怎么判断一条 case 是优质 case。
6. 假设评测集有 60 条 case，一开始只答对 45 条，迭代
   之后能答对 55 条，剩下 5 条是天花板一直答不上；但
   用户问题会越来越刁钻、不断有新问题进来，case 集
   要么变大要么替换旧的。新 case 是靠人肉选进来的吗。
7. 如果不想让 case 集越来越大，替换的时候怎么筛掉谁。

【三、AI 辅助 coding 设计题：DAG 任务调度器】
题面：给一份任务需求文档，现场设计一个支持依赖关系的
任务调度系统。明确说了可以全程用 AI 辅助 coding，考察
的是工程设计思路，不是手写代码。
1. 任务类型怎么定义，ID 和 type 分别怎么处理。
2. 分支 A→B、A→C，如果 B 失败了，下游任务要怎么处理。
3. 已经在执行中的任务怎么处理。

秋招信息差太大了，想找组织一起交流。同投 Agent／大模型岗的友友对对流程

#秋招# #面经# #校招# #快手# #agent# #大模型# #数据# #互联网大厂#
```
