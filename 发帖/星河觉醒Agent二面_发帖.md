**标题：** 星河觉醒秋招 Agent 二面

**正文（直接粘贴）：**

```
秋招正式岗。
没有八股，二面只挖了一个项目，从技术实现一路问到评测方法论、再问到线上
产品化，外加一道算法（面试官说不用写代码，讲思路就行）。
结果：未知，当天面完。

【一、多 Agent 问答系统项目相关提问】
1. 这个项目的背景是什么，为什么会选择做这么一个东西。
2. 你说 Claude Code、Codex 解决不了这个问题，具体指的是什么，做过
   验证吗。
3. 那你的方案是怎么解决这个问题的。
4. 如果把这套标准流程做成一个 skill 给到 Codex 或者 Claude Code，
   它们能做吗。
5. 具体的技术架构实现上是怎么做到这个东西的。
6. 这个方案听起来比较 SOP，当时为什么没想到用 workflow 的方式来做。
7. 为什么会变成一个 multi-agent 的架构，我的感觉是一个应该也够。
8. 你们的门禁校验现在都校验什么，校验的内容有哪些。

【二、幻觉相关追问】
1. 有关注过你们的幻觉率大概是多少吗。
2. 有了解过为什么幻觉会特别困难吗，除了 review 还有别的手段可以降低
   这个概率吗。
3. 有参考过类似 SPEC 这种方式吗，就是把它 SOP 化——标准的排查流程、
   标准的 checkpoint，用这个来降低出错。

【三、评测方法论与线上指标】
1. 你们这个准确率的评测，样本量有多少。
2. 这个准确率是跑多少轮得到的结果。
3. 上下波动会有多大。
4. 有观察过提升带来的分数大概是哪些维度的，以及为什么是这些维度能
   提升。
5. 如果希望这个数持续优化，比如做到 95% 以上，你觉得应该怎么做。
6. 你们这个算是一个 benchmark，有看过到真实线上生产环境之后，大家的
   反馈、或者问题解决率是什么样的吗。
7. 如果让你设计一个线上的指标，衡量这个 bot 做得好还是不好，应该
   怎么设计。

【四、算法（面试官说只讲思路，不用写代码）】
题面：给一棵树，共 n 个节点、n 个标记，标记初始任意分布在节点上，某些
   节点可能有多个、某些可能一个都没有。每次操作可以把一个标记沿一条边
   移动到相邻节点，求让每个节点恰好有一个标记的最少移动次数。先按二叉
   树讨论。（LC979 二叉树中分配硬币的推广）
1. 假设换成一棵 1000 叉树，根节点上有 5000 个标记，那应该怎么分。
```
