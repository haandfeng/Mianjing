**WXG 特色结论**：
1. **操作系统权重异常高**——协程/GMP、内存布局、手写 malloc、零拷贝、epoll 底层。作者 H 自评「wxg 太爱操作系统」与样本完全吻合。
2. **分布式一致性协议是硬门槛**——不是「了解即可」，会追问到选举细节，出现在面委面/总监面定档。
3. **LRU/LFU 是手撕 + 变体设计题**。
4. **LevelDB/LSM** 出现率远超其他公司。
5. 二面起从「会什么」转向「系统设计 + 工程决策 + 权衡」。

## 3. 微信支付特色题（支付/资金安全线）

- **微信付款码的安全性与唯一性如何保证**（C 三面）
- **设计微信红包系统 / 防止红包超发 / 高并发抢红包公平性**（D）
- **如何做数据对账**（D）
- **扣款系统设计：下游低 QPS、防超扣、排队 vs 直接失败**（H 三面，骨架见 [[资料/面经/腾讯/微信事业群/腾讯WXG后端实习三面]]）
- **分布式事务 / Redis 分布式锁风险 / 缓存与数据库一致性**（D）
- **32 位到 64 位机器迁移方案**（C 三面）

共性抽象：**「钱不能多也不能少」（超发/超扣/对账）+「下游扛不住怎么办」（限流/排队/降级取舍）** 是微信支付中后轮反复出现的两条主线。

> **2026-07-20 本人一面实测**（[[资料/面经/腾讯/微信事业群/腾讯微信支付一面_2026-07-20]]，底层支付链路）：基础面 = 零八股实操三连（手写环形队列 + AI 协作写重试封装 + 支付代码 review）。「资金安全」主线在**一面**就以 code review 形态出现（double 金额/单号唯一/转账原子性/**超时未决先查证再重试**）——修正「日常实习不必然考」：正式批/转正轨一面就考，只是换了题型。另证实：该组无专职测试岗，TDD/测试用例设计是核心考察；面试允许并要求 AI 协作（考 spec 澄清能力），与 K 样本「实操面」风格同源但更规范。

## 5. 备考建议（按优先级）

结合频次 + 「H 三面挂在操作系统深度」信号：

- **P0 操作系统深挖**：协程/GMP、内存布局、虚拟内存、epoll LT/ET 及底层、零拷贝、IPC。目标是扛住「手写 malloc」级追问 → [[Linux与IO模型]]
- **P1 分布式一致性**：Raft 全流程（选举/法定人数/日志复制）、Paxos vs Raft、宕机恢复、CAP 取舍。**第二轮修正：早轮常披着「Redis 哨兵选主」「MySQL 主从选主」的外衣出现；第三轮再修正：二面起裸考「Raft 机制/算法流程」已成常态——直接裸背全流程**
- **P2 手撕缓存/数据结构 + 语言八股**：LRU → LFU → 冷热变体（LRU-K）+ 手写 HashMap；**第三轮修正：语言八股跟组走（C++/Java/Go 组并存），按简历技术栈准备**——C++ 组考迭代器失效/智能指针/虚函数，Go 组考 goroutine/channel 底层/sync.Map/new vs make，Java 组考 GC。答不出语言题会被提前结束
- **P3 MySQL 事务+索引**：ACID 三 log、MVCC、B+ 树 vs 红黑树、回表、死锁；+主从选主/异步半同步复制 → [[MySQL索引与执行计划]] [[MySQL-MVCC与隔离级别]] [[InnoDB事务与锁]]
- **P4 网络**：三握四挥、TIME_WAIT/CLOSE_WAIT、TLS、URL 全流程；**第二轮补：HTTPS 里 RSA vs ECDHE、QUIC、Linux 收包全过程；第三轮升级：HTTPS 安全链路（数字签名/如何防篡改/中间人攻击/TLS 身份验证）连续 3 样本命中，提为 P0 级子项；另补 TCP 粘包处理、tcp_reuse/syn cookie**。微信支付一面网络权重尤其高 → [[TCP与HTTPS]]
- **P4.5 面委会/深水区系统设计底稿（第三轮新增）**：两道压轴要提前写底稿——①**手写进程内内存分配器**（申请/释放用什么数据结构、复杂度、大对象怎么分配，Q 面委会连环拷）；②**设计 KV 数据库**（CAP → 内存/磁盘数据结构选型 → 集群一致性与节点同步）。面委会风格：1h 深度八股+系统设计、无反问
- **P5 支付场景系统设计**：红包防超发、扣款防超扣、对账、限流三算法与被限流请求处理；按「现象→原理→方案→取舍」组织。**第二轮降半档：两个新的真·微信支付样本均未考到，更像正式批/中后轮特色，日常实习不必然考** → [[Redis分布式锁]] [[消息队列不丢不重]] [[缓存一致性]] [[限流熔断容错]]
- **P6 Redis+存储引擎**：数据结构、主从、哨兵 vs 集群、缓存三兄弟+布隆过滤器；LevelDB/LSM 基本原理 → [[Redis数据结构与大Key]] [[Redis缓存三大问题]]
- **P7 零散题库信号**：赛马、数组重复元素、手写策略模式、SQL 联查手感、密码加盐哈希
